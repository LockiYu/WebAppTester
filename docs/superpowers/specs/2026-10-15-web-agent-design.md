# Web 应用自主测试 Agent：首阶段设计

日期：2026-10-15  
状态：待书面审阅

## 目标与范围

从英文或中文自然语言场景出发，完成一次可审计的 Web 功能测试：自动规划检查点、通过 Playwright 操作页面、独立核验证据，并输出 PASS、FAIL 或无法判定。首阶段交付可运行的 Python CLI、三角色协作闭环、本地确定性演示网页和报告。随后接入 Streamlit、批量 CLI 与 4gaBoards 等正式目标应用。

课程评测固定使用 `deepseek-v4.1-flash`。本地开发允许选择 Ollama 小模型，以低成本验证协议和工具链；正式评测运行只能选择指定 DeepSeek 模型，不能混用其他模型。核心逻辑自行实现，不使用现成浏览器 Agent 或 Codex/Claude Code 等 Harness 作为运行基座。

## 已确定的约束

- 浏览器交互只通过 Playwright Python SDK；所有会改变页面状态的操作统一经过受控工具层。
- 每个场景最多 35 次浏览器操作。导航、点击、输入、选择、滚动、拖拽及失败重试均计数；DOM 读取和截图作为观察，不计为操作。到达上限后只能观察和出报告。
- 验收条件只能从原始场景提取；不得按场景编号找答案，也不得硬编码正式场景的完整路径。
- 正式输出须有结论、逐项依据、页面证据、Playwright Trace、操作轨迹及步数、耗时、Token 统计。
- 密钥和账号只从本地环境配置读取，不进入 Git；日志和截图元数据避免记录密码。

## 架构与职责

```text
CLI / Streamlit
      │
      ▼
Controller（确定性 Python 状态机）
  ├─ Planner：场景 → 前置条件、检查点、证据契约；处理证据缺口
  ├─ Executor：观察页面 → 提议一个合法动作或停止
  ├─ Verifier：引用真实观察 → 逐检查点 SAT / VIOLATED / UNKNOWN；提出缺口
  ├─ ModelProvider：Ollama / DeepSeek，统一消息及结构化输出接口
  ├─ BrowserGateway：唯一 Playwright 操作入口，负责计步、执行、异常分类
  └─ RunStore：状态台账、截图、DOM 摘要、Trace、报告
```

三个角色通过带版本的结构化对象交接，不自由修改彼此结果。Planner 和 Verifier 无浏览器写权限。Controller 不调用模型，且不允许角色直接绕过 BrowserGateway。单场景只有一个浏览器上下文，不并行操作同一页面。

## 数据协议

- `Scenario`：原句、目标 URL、可用账号引用、最大步数、运行配置。
- `Checkpoint`：唯一 ID、原句片段、必要性、预期状态、证据类型与当前 `SAT | VIOLATED | UNKNOWN`。
- `Observation`：时间、URL、可见 DOM 摘要、截图路径及页面状态指纹；原始证据只追加，不覆写。
- `Action`：受控动作类型、目标定位、参数、依据、对应检查点；不接受任意 Python 或 JavaScript。
- `ActionResult`：执行前后观察引用、成功与否、错误分类、累计步数。
- `GapRequest`：检查点 ID、缺失证据、建议观察位置和预计动作成本。
- `Verdict`：三态结论、每个检查点的证据引用、无法判定或违反条件的原因。

模型返回对象先做结构校验；不合法输出只允许有限次重新请求。仍不合法时结束为无法判定，不能凭空补出页面证据。

## 一次运行的数据流

1. CLI 读取场景和配置；Controller 创建运行目录、预算台账及 Playwright Trace。
2. Planner 从原句提取必要检查点和证据契约，保留原句映射。
3. Controller 获取页面观察，Executor 提议单个动作。Controller 先检查预算和动作类型，再预留一步并调用 BrowserGateway；失败同样消耗该步。
4. 每次动作后保存观察。Verifier 只用已保存的页面证据更新检查点；证据不足时发出 `GapRequest`，Planner 只围绕未完成必要检查点补查。
5. Controller 依据剩余步数、重复状态和重试次数批准补查或终止。所有必要检查点均 SAT 才 PASS；有充分证据证明应用违背原始要求才 FAIL；其他情况为无法判定。
6. RunStore 保存报告、截图及 Trace。CLI 显示简短摘要和完整报告路径。

## 错误与终止

定位失败、元素不可见、超时、模型输出错误、登录失败和预算用尽分别记录，不能直接归为应用缺陷。同一状态指纹及同一动作重复达到阈值时停止循环。模型服务不可达或浏览器异常时保留已取得的证据并给出无法判定报告。Controller 是 35 步上限的最终裁决者。

## 验证与阶段交付

首阶段用本地确定性演示网页完成“创建项目并在两个位置核验”的纵向测试；用模拟模型输出验证预算边界、失败重试计步和三态门控；再用 Ollama 跑一次真实模型调用。模型实际效果与协议正确性分开报告。

第二阶段加入 Streamlit、批量 CLI、历史记录与导出，再用已部署的 4gaBoards 3.2.16 和课程给的 5 个英文示例场景联调。正式 36 个场景只在发放后测试。对照实验依次加入证据契约、缺口反馈和预算仲裁，保持模型及环境一致。

首阶段验收：自然语言场景可从 CLI 启动；真实 Playwright Trace、截图、逐检查点证据和三态报告均落盘；包括失败重试在内不超过 35 步；缺证据不会报 PASS，执行失败不会自动报 FAIL。项目代码提交到用户指定的 GitHub `main`，本地测试环境密钥与课程材料不发布。
